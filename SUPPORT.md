# Support

Where to ask depends on what you need. Pick the smallest channel that fits.

## Questions (how do I…?)

- Read [`docs/START_HERE.md`](docs/START_HERE.md) and the 10-minute tour: [`docs/help/TOUR.md`](docs/help/TOUR.md) (Cursor: `/tour`).
- Why a file exists: [`docs/BEST_PRACTICES.md`](docs/BEST_PRACTICES.md).
- Using Windsurf, Antigravity, or another agent: [`docs/AGENT_PORTABILITY.md`](docs/AGENT_PORTABILITY.md).
- Product privacy and threat notes: [`docs/PRIVACY.md`](docs/PRIVACY.md), [`docs/THREAT_MODEL.md`](docs/THREAT_MODEL.md).
- Still stuck? Open a **GitHub Discussion** in the Q&A category (no secrets). A question issue is the fallback.

## Bugs

Use the **Bug Report** issue template. Include steps, the device (model / Android version), the command you ran (`bash scripts/verify.sh` or a VS Code **Verify** task), and a log snippet. Do not paste notification text, phone numbers, contact names, or coordinates.

## Vulnerabilities

Do **not** file a public issue. Follow [`SECURITY.md`](SECURITY.md) (private advisory).

## Contributing a fix

[`CONTRIBUTING.md`](CONTRIBUTING.md) — Conventional Commits, `bash scripts/verify.sh` before the PR.
